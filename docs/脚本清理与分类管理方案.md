# 脚本清理与分类管理方案

## 一、总体判定原则

| 类型 | 判定标准 | 归类建议 |
|---|---|---|
| **本地工具** | 可独立运行、有明确用户价值、由你制作或主动维护 | `tool` |
| **项目源码/模块** | 被其他文件 import、属于某个项目代码库的一部分 | `script` / `attachment` |
| **第三方应用源码** | 下载的完整应用（Photopea 整站 JS 等） | `attachment` |
| **模板/示例** | 仅用于复制参考，不直接承担业务功能 | `script` |
| **运维/排障脚本** | 可独立跑，但属于平台内部维护用途 | 可归为 `tool`，但单独子分类 |

**核心结论：不是"所有脚本都适合当工具"。** 聚创台里 46 个 tool 已经覆盖了主要入口；剩下 29 个 `script` + 116 个 `attachment` 大部分是项目源码和第三方文件，保持现状更合理。

## 三、附属工具 vs 独立工具判断

图片外自查发现的附属脚本：

| 脚本 | 所属项目 | 是否可独立运行 | 建议 |
|---|---|---|---|
| `hover-qa/modules/*.py` | HoverQA | 否（被 import） | 保持 `attachment` |

| `hover-qa/fix_db_ids.py` | HoverQA / 脚本管理 | 是 | **可提升为 tool**，分类 **"脚本管理中台 · 平台运维"** |
| `hover-qa/register_to_platform.py` | 脚本管理 | 是 | **可提升为 tool**，分类 **"脚本管理中台 · 平台运维"** |

## 四、AI 助手启动脚本冗余归并方案

当前冗余模式：**一个应用配多个启动入口**。

| 应用 | 当前入口 | 归并后 |
|---|---|---|
| **HoverQA** | 启动 HoverQA、start-hover-qa.vbs、hover_qa_core.py、停止 HoverQA | 保留 **"启动 HoverQA" + "停止 HoverQA"**；`hover_qa_core.py` 仍保留为"核心引擎"工具；`start-hover-qa.vbs` 降级为附件 |
| **多 Agent 工作台** | start_workbench.cmd、stop_workbench.cmd | 保留成对，无需合并 |
| **Prompt Optimizer** | start_prompt_optimizer.cmd、run_prompt_optimizer_dev.cmd | 合并为 **一个工具 + `--dev` 参数**，或保留两者但明确标注"生产/开发" |
| **Photopea** | 启动/停止 | 保留成对 |

**建议**：每个"服务/应用"在工具面板里最多出现 **1 个启动 + 1 个停止 +（可选）1 个核心引擎**。多余的实现层脚本全部沉到 `attachment`。

## 五、聚创台内部脚本分类建议

`D:\聚创台` 当前**不在扫描根目录**里，因此 `server.js`、`index.html`、`test-scan.js`、`start.bat` 未被聚创台扫描为资源。但用户桌面/AI-Workspace 里有一个 `聚创台.bat` 被识别为 tool。

| 文件 | 是否应加入工具 | 建议 |
|---|---|---|
| `D:\聚创台\start.bat` | **是** | 这是启动聚创台本身的入口，应作为 tool 加入，分类 **"工作台 · 启动器"** |
| `D:\聚创台\server.js` | 否 | 工作台后端实现，归入 `file` 或直接排除 |
| `D:\聚创台\index.html` | 否 | 前端实现，归入 `file` |
| `D:\聚创台\test-scan.js` | 否 | 测试脚本，归入 `script` 或直接排除 |
| `D:\AI-Workspace\hub\聚创台.bat` / 桌面 `聚创台.bat` | 是 | 已识别为 tool，可作为快捷入口保留 |

**结论**：不要把聚创台自身源码批量归为工具，只把 `start.bat` 这种真正的启动入口暴露出来。

## 七、后续管理建议

1. **引入 `tool` / `internal` / `public` 标签**：给工具加 visibility 字段，内部运维脚本默认不显示在首页。
2. **manifest 优先**：脚本管理平台下的工具以 `*.manifest.json` 为准，未配 manifest 的脚本不自动升为 tool。
3. **项目源码目录加排除**：`AI-Workspace/**/backend/**`、`AI-Workspace/**/modules/**` 等目录里的 `__init__.py`/`schemas.py` 不应参与扫描，减少噪音。
4. **周期性自检**：每月跑一次审计，检查新增 script/attachment 里是否有独立运行价值，及时补升或维持现状。
